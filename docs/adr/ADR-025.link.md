# ADR-025 — AI Agent Bridge / MCP Server for Ecosystem Introspection (link stub)

**Authoritative copy:** [`../../../exeris-ai-bridge/docs/adr/ADR-025-ai-agent-bridge.md`](../../../exeris-ai-bridge/docs/adr/ADR-025-ai-agent-bridge.md)

ADR-025 is a **cross-repo** decision owned by `exeris-ai-bridge`. It binds this platform repository because the `lsp:*` tool family in the bridge proxies `exeris-platform-lsp` over JSON-RPC, making the LSP semantic index a second-class consumer surface (the first being Studio itself).

## Why this stub exists

Today the LSP server has one consumer (Studio frontend). After ADR-025 accepts, it gains a second consumer (the agent bridge). Platform reviewers should find this contract change documented next to the LSP code without needing to know that the authoritative ADR lives in a sibling repo.

## When to consult ADR-025 from exeris-platform

- Any PR that changes the LSP JSON-RPC surface (`exeris-platform-lsp/...`) — verify the change is forward-compatible with the bridge proxy, or amend ADR-025 and the bridge tool definitions.
- Any PR that proposes deprecating or restructuring `@ExerisDomain` source-model APIs exposed via LSP — the agent surface (`lsp:list_domains`, `lsp:describe_domain`) depends on this contract.
- Any proposal to move Studio backend logic into the agent bridge or vice versa — they consume the same LSP index but serve structurally different surfaces (human vs agent). Don't conflate them.
- Any RFC that adds new agent-facing telemetry from Studio — coordinate with the bridge owner to avoid creating overlapping surfaces.

## Engineering status

ADR-025 is **ACCEPTED** (2026-05-15). The platform-side companion — the read-only `exeris/*` LSP slice that the bridge's `lsp:*` family consumes — has **landed** in `exeris-platform-lsp` (`feat/lsp-readonly-slice`). Its method surface and wire shapes are pinned by the canonical ADR's **2026-06-24 amendment** ("`lsp:*` Binds to the Read-Only `exeris/*` LSP Slice"):

- `exeris/domains` → `DomainSummary[]` (`qualifiedName`, `simpleName`, `packageName`, `sourcePath`)
- `exeris/domainDescribe` `{ qualifiedName }` → `DomainDescription` (summary fields + `fields[]`, `actions[]`, `artefacts[]`)
- `exeris/actions` → `ActionSummary[]` (`owningDomain`, `name`, `httpMethod`, `resultType`, `params[]`)

These sit under the `exeris/*` namespace (the earlier `workspace/exeris*` working names are superseded). Write-back (`exeris/applyMutation`) is reserved by the method-surface contract but is **not** part of this slice and must not be consumed by the bridge. Any rename or shape change to these three methods is an LSP-surface change → amend the canonical ADR-025 and the bridge tool definitions before merging (see "When to consult" above).
