# ADR-085 — Federated Documentation Architecture and Repo-Hygiene Standards (link stub)

**Authoritative copy:** [`exeris-docs/adr/ADR-085-documentation-architecture-and-repo-hygiene-standards.md`](https://github.com/exeris-systems/exeris-docs/blob/main/adr/ADR-085-documentation-architecture-and-repo-hygiene-standards.md)

ADR-085 is a **platform-scope** decision owned by `exeris-docs`. It binds every Exeris repository,
this one included: documentation stays federated in each repository's `docs/` tree, carries
validated frontmatter, and commits, pull requests, Javadoc, ADRs and agent files follow the
standards in
[`exeris-docs/standards/`](https://github.com/exeris-systems/exeris-docs/tree/main/standards).
Structure is gated in CI; prose is reviewed.

## Why this stub exists

The obligations land in files at this repository's root — `AGENTS.md`, `CONTRIBUTING.md`, the ADR
filenames under `docs/adr/` — but the decision behind them is not written here. A reader of
`docs/adr/` should find ADR-085 without needing to know which repository owns it. ADR-085's
Engineering Protocol item 1 asks for this stub by name.

## What is adopted here, and what is not

**Adopted:**

- **§I.29 — agent files.** [`AGENTS.md`](../../AGENTS.md) is the canonical agent entry point and
  [`.agents/`](../../.agents) is the canonical semantic source, on manifest version 2 with
  `exeris-agents` 2.1.0 vendored and digest-verified. `.claude/` holds generated adapters carrying a
  do-not-edit marker, plus provider-owned configuration; `CLAUDE.md` is a pointer. The adapters are
  rendered and checked by the shared renderer of `exeris-systems/exeris-agents`; `docs-lint` fails
  on an adapter that differs from its source.
- **§I.30 and §K — AI provenance and contributor terms.**
  [`CONTRIBUTING.md`](../../CONTRIBUTING.md) states the Apache-2.0 licence, the `Signed-off-by:`
  requirement and the AI-provenance rules.
- **§B.7 frontmatter** on every document, checked by `docs-lint` in `strict` mode.
- **§C.11 reusable workflows.** `.github/workflows/guardrails.yml` calls `docs-lint`, `commit-lint`,
  `pr-body-check` and the organisation's review, published as one verdict with this repository's
  rules in [`docs/repo-review-rules.md`](../repo-review-rules.md); `.github/workflows/issues.yml`
  syncs the label taxonomy.

**Not yet adopted — tracked as `[DOC DEBT]`:**

- **The Javadoc and TSDoc gates** of §C.11. Neither is called here yet.
- **§H.27 CHANGELOG `Breaking` sections.** This repository keeps no CHANGELOG.

## When to consult ADR-085 from exeris-platform

- Any change to `AGENTS.md`, `.agents/**` or a provider directory — the schema's hard rules decide
  where a rule may be authored, and §I.29 forbids `.claude/` becoming a second source.
- Any new document under `docs/` — filename patterns (§G.22), the registry-row-first rule (§G.23)
  and the frontmatter schema (§B.7) all apply.
- Any cross-repo link: an absolute `https://github.com/exeris-systems/<repo>/blob/<branch>/<path>`
  URL naming the branch.
- Any public document that would link into an enterprise-private repository — §A.3 and §G.24 make
  ADR-020's rule machine-checked.
